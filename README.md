# griipbuddy-prisma-backend

E-commerce API for the GriipBuddy **admin panel** (`griipbuddy-admin-new`) and **storefront** (`special-biye`).
Express · TypeScript · Prisma · PostgreSQL · optional Redis (rate limits + BullMQ jobs).

It serves the same API as `project-server` (same paths, request bodies and response shapes), so both
frontends work without changes. See [`docs/PLAN.md`](docs/PLAN.md) for the design and where each part came from.

## Run locally

```bash
docker compose -f docker-compose.dev.yml up -d   # PostgreSQL (+ test database)
cp .env.example .env                             # then set JWT_ACCESS_SECRET / JWT_REFRESH_SECRET
npm install                                      # also runs `prisma generate`
npm run db:deploy                                # apply migrations
npm run db:seed                                  # roles, super admin, sample catalog + stock
npm run dev                                      # http://localhost:5007
```

Login: **01700000000 / Admin@12345** (change with `SEED_ADMIN_*` before seeding).
Redis is optional: set `REDIS_URL` to use it, or `docker compose -f docker-compose.dev.yml --profile redis up -d`.

Point the frontends at it (`.env.local` in each):

| App        | Variable                                                   |
| ---------- | ---------------------------------------------------------- |
| Admin      | `NEXT_PUBLIC_BASE_SERVER_API=http://localhost:5007/api/v1` |
| Storefront | `NEXT_PUBLIC_API_BASE_URL=http://localhost:5007/api/v1`    |

Both also need `localhost:5007` allowed under `images.remotePatterns` in `next.config.ts` for local uploads.

```
├─ modules/             index.ts re-exports every module
│  └─ <name>/           <name>.route.ts · .controller.ts · .service.ts · .validation.ts · index.ts
├─ routes/index.ts      moduleRoutes = [{ path, route }] + /health
├─ middlewares/         auth, globalErrorHandler, notFound, rateLimiter, requestLogger, validateRequest, validateInput
├─ jobs/                queue (BullMQ or inline), job handlers, cron
├─ config/              env.ts (.env, validated with Zod) · appConfigs.ts (fixed settings) · index.ts
├─ constants/           pagination, permissions & roles

└─ views/               email templates (Handlebars)
tests/                  Vitest + Supertest integration tests
```

**Module pattern:** the route wires middleware → the controller reads the request and calls the
service → the service holds all business logic and database access → `sendResponse` shapes the reply.

Modules: `user` · `customer` (phone + OTP login) · `role` · `permission` · `upload` · `businessLocation` ·
`category` · `subCategory` · `brand` · `returnPolicy` · `product` · `stock` · `order` · `purchase` ·
`supplier` · `cms` · `review` · `faq` (product Q&A).

### Conventions

- **Responses:** `{ statusCode, success, message, data, meta? }`; errors add `errorMessages[]`.
- **IDs:** every object has both `_id` and `id`. Foreign keys are exposed under the relation name —
  the object when included, the id otherwise (`brand_id` → `brand`), like the old Mongo API.
- **Money** is `Decimal(12,2)` in the database and a number in JSON. Prices and totals are always
  computed on the server.
- **Stock** is one row per variant × location (`available` + `reserved`). Orders reserve stock in a
  transaction; status changes move it (shipped → removed, cancelled → released, returned → restocked).
  CHECK constraints keep quantities ≥ 0.
- **Public vs admin:** storefront reads and `POST /order` are public; everything else needs a staff
  token and the matching permission (`staff("<key>")` from `src/middlewares/auth.ts`).

## How to create a new API (step by step)

Example: a **Coupon** CRUD for the admin. Copy these 9 steps for any new feature; only the names change.

```
request → route (auth + validation) → controller (reads req) → service (logic + database) → response
```

### 1. Add the table: `prisma/schema/coupon.prisma`

```prisma
model Coupon {
  id        String   @id @default(cuid())
  code      String   @unique
  discount  Decimal  @db.Decimal(12, 2)
  is_active Boolean  @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("coupons") // table name: plural snake_case
}
```

Then create the table:

```bash
npm run db:migrate -- --name coupons   # makes prisma/migrations/<date>_coupons and updates the Prisma client
```

### 2. Create the module folder

```
src/modules/coupon/
├─ coupon.validation.ts   what the request body must look like
├─ coupon.service.ts      the logic + database
├─ coupon.controller.ts   reads the request, calls the service, sends the response
├─ coupon.route.ts        URLs + who may call them
└─ index.ts               exports
```

### 3. Validation: `coupon.validation.ts`

Bad input is rejected with a 400 before your code runs. A schema can check `body`, `query` and `params`.

```ts
import { z } from "zod/v3";
import { listQuery } from "@/middlewares/validateInput";

const code = z.string().trim().min(3, "Code must be at least 3 characters.").max(30);
const discount = z.coerce.number().positive("Discount must be more than 0.");

export const CouponValidation = {
  // GET /coupon?is_active=true&page=1 … (page/limit/sort/search come from listQuery)
  listSchema: z.object({
    query: listQuery.extend({
      is_active: z.enum(["true", "false"], { message: "is_active must be true or false" }).optional(),
    }),
  }),
  createSchema: z.object({
    body: z.object({ code, discount, is_active: z.boolean().default(true) }),
  }),
  updateSchema: z.object({
    body: z
      .object({ code, discount, is_active: z.boolean() })
      .partial() // every field optional
      .refine((body) => Object.keys(body).length > 0, "Nothing to update."),
  }),
};
```

### 4. Service: `coupon.service.ts`

All logic and database work lives here. Keep each function simple: **find → check → save → return**.
Throw `notFound(...)` / `badRequest(...)`; the error handler turns them into proper responses.

```ts
import type { Coupon, Prisma } from "@prisma/client";
import { prisma } from "@/shared/prisma";
import { badRequest, notFound } from "@/errors/ApiError";
import { NEWEST_FIRST, filterWhere, paginate, searchWhere, sortBy } from "@/helpers/queryBuilder";
import type { IPagination } from "@/interfaces/pagination";

type CouponInput = { code: string; discount: number; is_active?: boolean };

/** List with search, filter, sort and pagination → { data, meta }. */
const getAll = async (pagination: IPagination, search?: string, isActive?: boolean) => {
  const where: Prisma.CouponWhereInput = {
    ...searchWhere<Prisma.CouponWhereInput>(search, ["code"]), // ?search=
    ...filterWhere<Prisma.CouponWhereInput>({ is_active: isActive }), // skipped when undefined
  };
  const orderBy = sortBy(pagination, ["code", "discount", "createdAt"], NEWEST_FIRST); // ?sortBy=&sortOrder=

  const result = await paginate(pagination, {
    findMany: (page) => prisma.coupon.findMany({ where, orderBy, ...page }), // ?page=&limit=
    count: () => prisma.coupon.count({ where }),
  });
  return result;
};

const getById = async (id: string): Promise<Coupon> => {
  const result = await prisma.coupon.findUnique({ where: { id } });
  if (!result) throw notFound("Coupon");
  return result;
};

const create = async (input: CouponInput): Promise<Coupon> => {
  const code = input.code.toUpperCase();

  const existing = await prisma.coupon.findUnique({ where: { code } });
  if (existing) throw badRequest("This coupon code already exists.", "code");

  const result = await prisma.coupon.create({ data: { ...input, code } });
  return result;
};

const update = async (id: string, input: Partial<CouponInput>): Promise<Coupon> => {
  await getById(id); // 404 if it doesn't exist

  const data = { ...input, ...(input.code ? { code: input.code.toUpperCase() } : {}) };
  const result = await prisma.coupon.update({ where: { id }, data });
  return result;
};

const remove = async (id: string): Promise<void> => {
  await getById(id);
  await prisma.coupon.delete({ where: { id } });
};

export const CouponService = { getAll, getById, create, update, remove };
```

### 5. Controller: `coupon.controller.ts`

Only reads the request and sends the response, no logic. `catchAsync` passes any error to the error handler.

```ts
import type { Request, Response } from "express";
import httpStatus from "http-status";
import catchAsync from "@/shared/catchAsync";
import sendResponse from "@/shared/sendResponse";
import { paginationHelpers } from "@/helpers/paginationHelper";
import { queryString } from "@/helpers/queryHelper";
import { CouponService } from "./coupon.service";

const getAll = catchAsync(async (req: Request, res: Response) => {
  const pagination = paginationHelpers.calculatePagination(req); // page, limit, sortBy, sortOrder
  const search = queryString(req, "search");
  const status = queryString(req, "is_active");
  const isActive = status === undefined ? undefined : status === "true";

  const result = await CouponService.getAll(pagination, search, isActive);
  sendResponse(res, {
    statusCode: httpStatus.OK,
    success: true,
    message: "Coupons fetched successfully.",
    data: result.data,
    meta: result.meta,
  });
});

const getById = catchAsync(async (req: Request, res: Response) => {
  const result = await CouponService.getById(req.params.id);
  sendResponse(res, { statusCode: httpStatus.OK, success: true, message: "Coupon fetched.", data: result });
});

const create = catchAsync(async (req: Request, res: Response) => {
  const result = await CouponService.create(req.body);
  sendResponse(res, {
    statusCode: httpStatus.CREATED,
    success: true,
    message: "Coupon created.",
    data: result,
  });
});

const update = catchAsync(async (req: Request, res: Response) => {
  const result = await CouponService.update(req.params.id, req.body);
  sendResponse(res, { statusCode: httpStatus.OK, success: true, message: "Coupon updated.", data: result });
});

const remove = catchAsync(async (req: Request, res: Response) => {
  await CouponService.remove(req.params.id);
  sendResponse(res, { statusCode: httpStatus.OK, success: true, message: "Coupon deleted." });
});

export const CouponController = { getAll, getById, create, update, remove };
```

### 6. Routes: `coupon.route.ts`

Each line = **URL + who can call it + input check + controller**. Ids in the URL (`/:id`, `/:productId`) are
checked for you, so `/coupon/abc` is a 400 "Invalid id." without touching the database.

```ts
import express from "express";
import { staff } from "@/middlewares/auth";
import validateRequest from "@/middlewares/validateRequest";
import { CouponController } from "./coupon.controller";
import { CouponValidation } from "./coupon.validation";

// /coupon
const router = express.Router();

router.get(
  "/",
  ...staff("coupon.view"),
  validateRequest(CouponValidation.listSchema), // ?is_active=maybe → 400
  CouponController.getAll
);
router.get("/:id", ...staff("coupon.view"), CouponController.getById);
router.post(
  "/",
  ...staff("coupon.create"),
  validateRequest(CouponValidation.createSchema),
  CouponController.create
);
router.patch(
  "/:id",
  ...staff("coupon.update"),
  validateRequest(CouponValidation.updateSchema),
  CouponController.update
);
router.delete("/:id", ...staff("coupon.delete"), CouponController.remove);

export const CouponRoutes = router;
```

Who can call it:

| Use                       | For                                                          |
| ------------------------- | ------------------------------------------------------------ |
| nothing                   | public (storefront), e.g. `router.get("/public", …)`         |
| `...staff("coupon.view")` | admin staff with that permission (super admin always passes) |
| `...staff(["a", "b"])`    | staff with **any** of these permissions                      |
| `customer`                | a logged-in shopper (phone + OTP login)                      |

Put fixed paths (`/public`, `/admin/all`) **before** `/:id`, or `/:id` will catch them.

## Search, sort and pagination

Every list endpoint takes the same query string:

```
GET /api/v1/brand/admin/all?searchTerm=nike&page=2&limit=20&sortBy=name&sortOrder=asc
```

| Query                   | What it does                                                                | Default          |
| ----------------------- | --------------------------------------------------------------------------- | ---------------- |
| `page`                  | Which page (1, 2, 3 …)                                                      | `1`              |
| `limit`                 | Rows per page (1–1000)                                                      | `10` (per route) |
| `sortBy`                | Field to sort by; only fields the service allows, others are ignored        | newest first     |
| `sortOrder`             | `asc` or `desc`                                                             | `desc`           |
| `search` / `searchTerm` | Text search (case-insensitive, matches part of a word) across chosen fields | no search        |
| anything else           | Exact filters, e.g. `status=PENDING`, `is_active=true`                      | no filter        |

The service returns the rows and the page info together:

```json
{
  "data": [ … 20 brands … ],
  "meta": { "page": 2, "limit": 20, "total": 57, "totalPage": 3 }
}
```

The frontend shows "page 2 of 3" from `meta`, and asks for `page=3` next. Most admin lists send this whole object as
the response's `data` (so `data.data` and `data.meta`). A few (products, purchases, reviews, FAQs, customer orders)
put `meta` next to `data` at the top level, because that's where their screens read it. New endpoints: use the
top-level style, like the Coupon example.

### How it works in the code

```
request ──► controller ──────────────────────────► service ──────────────────────────► database
            calculatePagination(req)               searchWhere  → WHERE name ILIKE '%nike%'
              → { page, limit, skip, sortBy,       filterWhere  → AND is_active = true
                  sortOrder }                      sortBy       → ORDER BY name ASC
            queryString(req, "searchTerm")         paginate     → LIMIT 20 OFFSET 20 + COUNT(*)
```

| Helper (`src/helpers`)                      | Job                                                                         |
| ------------------------------------------- | --------------------------------------------------------------------------- |
| `paginationHelpers.calculatePagination`     | Reads `page`, `limit`, `sortBy`, `sortOrder` → `{ page, limit, skip, … }`   |
| `queryString(req, "name")`                  | One query value as trimmed text; empty / `"undefined"` / `"null"` → nothing |
| `searchWhere(text, ["name", "brand.name"])` | Search one text across several fields (dotted = a related table)            |
| `filterWhere({ status, is_active })`        | Exact filters; empty values are skipped, so "no filter" just works          |
| `sortBy(pagination, allowed, NEWEST_FIRST)` | The client's sort, only for `allowed` fields (no sorting by hidden columns) |
| `paginate(pagination, { findMany, count })` | Fetches the page and the total together → `{ data, meta }`                  |

A full example is the Coupon service in [How to create a new API](#4-service-couponservicets).

### Bad values are rejected

`src/middlewares/validateInput.ts` checks the shared query fields and URL ids for **every** route (nothing to add
per route). Empty values (`?page=`, `?limit=undefined`) count as "not sent".

| Request                         | Response                                       |
| ------------------------------- | ---------------------------------------------- |
| `?limit=abc`                    | 400 `limit must be a whole number`             |
| `?limit=5000`                   | 400 `limit must be between 1 and 1000`         |
| `?sortOrder=up`                 | 400 `sortOrder must be asc or desc`            |
| `?startDate=yesterday`          | 400 `startDate must be a date like 2024-12-31` |
| `?min_price=abc`                | 400 `min_price must be a number`               |
| `?page=1&page=2`                | 400 `page must be sent once`                   |
| `/brand/not-an-id`              | 400 `Invalid id.` (no database query)          |
| `/brand/<valid but unknown id>` | 404 `Brand not found.`                         |

For a route's **own** query fields (like `is_active` or `status`), add `query: listQuery.extend({ … })` to its
schema and use `validateRequest` (see step 3 above).

## API docs (Swagger)

Open **http://localhost:5007/docs**: every endpoint with its body, query and path fields, who may call it
(🌐 public · 🔒 staff + permission · 🔒 customer) and a **Try it out** button. Log in, copy `access_token`,
click **Authorize** and paste it. The raw OpenAPI file is at `/docs.json` (import it into Postman, or generate
a typed frontend client from it).

```
swagger/
├─ build.ts        reads the real routes: path, method, Zod schema (validateRequest), auth/staff/customer
├─ endpoints.ts    optional summaries and notes per endpoint, e.g. "POST /customer/otp/send"
├─ generate.ts     `npm run docs` → writes openapi.json
└─ openapi.json    the generated docs (committed; the server shows this file)
```

- New endpoints appear automatically — just run `npm run docs` after changing routes or schemas.
  A test fails if `openapi.json` is out of date, so it can't be forgotten.
- To explain an endpoint, add a line to `swagger/endpoints.ts` (`list: true` adds page/limit/search/sort).
- On by default in development, off in production. `API_DOCS=true` turns it on anywhere.

## Error tracking (Sentry)

Set `SENTRY_DSN` (sentry.io → new project → Node.js / Express → copy the DSN) and restart. Sentry then emails
you about, with the stack trace, URL and user id:

- request errors that became a **500** (not normal 4xx like "not found" or wrong password)
- background jobs that failed after all retries, and failed cron runs
- crashes (uncaught exceptions, unhandled promise rejections) and startup failures

Passwords, OTP codes, tokens, cookies, local variables and job data (SMS texts) are never sent — see
`src/shared/sentry.ts`. To report an error yourself: `reportError(err, { tags: { feature: "checkout" } })`.
Empty `SENTRY_DSN` (and every test run) = off.

## Background work

- **Jobs** (`src/jobs`): customer SMS on order placed / shipped / delivered / cancelled. With Redis they
  run through BullMQ (3 retries, exponential backoff); without Redis they run in-process.
- **Cron** (Asia/Dhaka, Postgres advisory lock so only one instance runs each job):
  - 09:00 — low-stock email to `ADMIN_ALERT_EMAILS`
  - 03:30 — delete audit logs older than `AUDIT_LOG_RETENTION_DAYS`

## Deploy

**Docker (recommended).** On the server:

```bash
cp .env.example .env        # NODE_ENV=production, real secrets, POSTGRES_PASSWORD, CORS_ORIGINS, SERVER_BASE_URL
docker compose up -d --build
docker compose exec api npm run db:seed    # first time only: roles + super admin
```

The container applies migrations on start (`RUN_MIGRATIONS=false` to disable), runs as a non-root
user, exposes a health check at `/api/v1/health`, and shuts down gracefully on `SIGTERM`.
Put nginx (or another TLS proxy) in front; `TRUST_PROXY=1` makes rate limits use the real client IP.

**CI/CD (GitHub Actions).**

- `ci.yml` — every push/PR: lint, type-check, migrations from scratch, tests on Postgres, build, Docker build.
- `deploy.yml` — push to `production`: build → push to GHCR → SSH to the server → pull + restart → health check.
  Secrets: `SSH_HOST`, `SSH_USER`, `SSH_KEY`, `DEPLOY_PATH`.
